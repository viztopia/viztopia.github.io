# Design Context — viztopia.github.io

## Target audience
Visitors to Yuguang Zhang's portfolio. Mostly: curators, collaborators, residency/fellowship reviewers, grad-school applicants to ITP-adjacent programs, fellow artists in the generative / HCI / speculative-design space. Secondary: press, students researching his work, casual readers arriving from shared links.

## Use cases
- See what he's made, in depth (project pages carry the real weight)
- Confirm he's legitimate (awards, press, exhibitions)
- Get a feel for the *person* behind the work — the site tone should do this, not an About page alone
- Contact him / link to him
- Skim on phone; study on laptop

## Brand personality / tone — three concrete words
- **Observant.** His projects are about looking — at clouds, at sleeping bodies, at bedsheet imprints, at objects that remember. The site should feel looked-at too: attention to small things, hairlines, spacing, a willingness to pause.
- **Speculative.** "I imagine what life could be with alternative intelligence." Not instructional. Invites rather than asserts. Leaves room for the reader to wonder.
- **Handmade.** Every page is hand-coded by copying a template. Individual tuning per project is fine. Small asymmetries are okay. The site shouldn't feel like it came from a generator.

Avoid: "minimal", "modern", "elegant" (dead categories per impeccable guidance). Avoid generic portfolio-template moves (dark hover overlays over every thumbnail, generic `#4d638c` link blue, equal-weight uppercase letter-spaced labels).

## What the user explicitly asked for
- UX modernization + loading improvements; **not** a full redesign
- Maintain the current vibe (white ground, minimal nav, lots of air)
- Open to: font choice, font sizes, layout adjustments, subtle elegant transitions on all elements, more details, better mobile
- **Key pain point**: full-width image stacks feel "bulky" — especially when multiple horizontals stack, and worst when a portrait image appears after several landscapes. Needs a reusable mechanism to interweave text and photo 灵动地 (nimbly / fluidly) across future projects too
- Color: stay black and white, but "play with the grayscale" is welcome
- Links currently bolded; user is open to suggestions

## Design decisions

### Typography
Keep **Work Sans** as the only family (maintains current vibe). Extend to weights 200/300/400/500 (currently only 300/400/700). Use:
- `h1` — 200 weight, fluid `clamp(2.5rem, 1.6rem + 4vw, 4.75rem)` (~40→76px), negative letter-spacing for optical correction
- `h2` — 300 weight, fluid `clamp(1.5rem, 1.15rem + 1.6vw, 2.25rem)` (~24→36px)
- `h3` — 400 weight, 14–16px, uppercase with 0.14em letter-spacing (labels only: "AWARDS", "TOOLS")
- body `p` — 300 weight, fluid 16→17px, line-height 1.65
- `p.lede` — italic, 18→21px, 300 weight (keeps current "intro paragraph in italic" pattern, just refined)
- `p.note` — 13px muted, up to 40ch wide (captions, credits)

No serif display face. User wants current vibe preserved; typography does not need to carry character — the layout does.

### Grayscale ramp
5 neutrals, all warm-biased (slight yellow tint) instead of dead `#000`/`#fff`:
- `--ink: #0a0a0a` (near-black, warmer than pure)
- `--text: #1a1a1a`
- `--text-muted: #6a6a6a`
- `--hairline: rgba(0, 0, 0, 0.08)`
- `--paper: #fafaf8` (off-white background; if we apply it)

### Links
Drop generic `#4d638c` blue. Monochrome treatment:
- body weight stays 300; link weight **400** (subtle emphasis, not bold 700)
- underline: `text-decoration-color: rgba(0,0,0,.25); text-decoration-thickness: 1px; text-underline-offset: 3px`
- hover: color stays; underline → `currentColor`, thickness → 2px, 300–400ms ease

### Motion — house rules
- `--t-fast: 200ms` for tiny UI shifts
- `--t-med: 400ms` for color/opacity on hover
- `--t-slow: 700ms` for transforms, reveals, image scales
- `--ease-out: cubic-bezier(0.2, 0.8, 0.2, 1)` as the single site-wide easing
Apply these universally: any property that animates should use a token, not a bespoke duration.

### Editorial layout vocabulary (project pages)
Wrap project content in `<article class="project">`. Inside, the following figure classes are the only layout primitives:

| Class | Meaning | Rail |
|---|---|---|
| `.cover` | Hero image, first on the page | full-bleed |
| `.wide` | Standard horizontal image (default) | content width |
| `.pair` | Two images side by side 50/50 | content width |
| `.triptych` | Three images in a row | content width |
| `.portrait` | Vertical image, centered, capped at ~55% width + 85vh height | within content |
| `.aside-left` / `.aside-right` | Image on one side, paragraph on the other | content width, 2-col |
| `.inset` | Small image (~33%) alongside paragraph | content width, 1/3 + 2/3 |
| `.video` | 16:9 iframe container (Vimeo / YouTube) | content width |

Grid: CSS Grid with 3 named columns — `[full-start] gutter [wide-start] content(max 72rem) [wide-end] gutter [full-end]`. Every child lands on `wide` by default; figures opt into other rails.

Mobile (< 48rem): all multi-column variants collapse to a single column. `.portrait` widens to 85%.

### Solving the "bulky" problem
The old pattern was every image → `col-md-12 > img-responsive` → full width. That creates a wall of rectangles. The editorial vocabulary gives the writer a reason to choose differently per photo:
- Three exhibition shots? `.triptych` instead of three `.wide`.
- Horizontal photo plus a caption paragraph? `.aside-left` — text is not just a caption, it sits alongside.
- Vertical photo? `.portrait` — centered, not forced to fill width.
- Two related shots? `.pair` instead of two stacks.
- Supporting detail? `.inset` — small, in line with text.

### What is NOT changing
- Nav structure + active state
- Site architecture (projects/experiments split)
- Copy-a-page-to-add-a-new-project workflow
- Per-page inline `<style>` tweak pattern (rarely used, no need to remove)
- Content — text, images, exhibitions, credits all stay
- Other 39 project pages — they continue using the legacy Bootstrap `#single-project` styles. Convert them to `.project` vocabulary one at a time as time allows.

## Rollout strategy
- Phase 2A: `nephophile.html` + `non-human.html` as reference conversions. User reviews.
- Phase 2B (future): `index.html` and `about.html` get the same treatment (index uses CSS Grid for portfolio thumbs, about gets editorial paragraph scale).
- Phase 2C (future): sweep remaining project pages into `.project` vocabulary. No rush — legacy pages still work. When user edits an old page they can convert it in place.
- Phase 2D (future): once every live page is on `.project`, drop `css/bootstrap.min.css` entirely and delete the dead `#contact` / `#blog` / `.blog-*` rules from `style.css`.
